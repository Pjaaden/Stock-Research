# 季度财报 CSV 存档规范（Stock-Research 项目标准）

> 定位：本项目**结构化数据层**的统一采集规范，与研究 HTML（研究报告层）、`data/*.json`（工作台字段）并列，互不替代。
> **适用范围：所有研究标的**——`data/companies.json` 内全部公司（含 active 与 hidden）；行业研究目录（如 `草甘膦_行业研究/`）按需参照同一规范。
> **强制程度：凡新增或更新财报（季报 / 半年报 / 年报），均须按本规范同步 CSV 归档**，不得只写研究 HTML 而跳过结构化归档。尚未建档的标的，应在下次触及该标的（出新报告 / 财报更新 / JSON 同步）时一并补齐。
> 建档进度与清单：见 **§六**。

---

## 一、目录与文件约定

每个标的在其 `research_folder` 下建立：

```
<research_folder>/
└── data/
    └── quarterly/
        ├── README.md                      # 数据字典 + 该标的建档信息
        ├── <code>_income_statement.csv    # 合并利润表（经营收益表）
        ├── <code>_balance_sheet.csv       # 合并资产负债表
        ├── <code>_cashflow_statement.csv  # 合并现金流量表
        └── <code>_segment_revenue.csv     # 分部收入（分产品/分地区/分主体，视披露口径）
```

- 文件名为**标的代码小写 + 表名**，如 `lingxiao_income_statement.csv`、`sailun_income_statement.csv`。
- 全部 CSV：UTF-8 **带 BOM**（Excel / Numbers 直接打开中文不乱码）。
- 统一 **long-format**（一行为一个 `period` × 一个科目），便于追加与程序化读取。
- 目录固定为 `<research_folder>/data/quarterly/`，与 `research_folder` 严格一致（`research_folder` 必须等于仓库内真实目录名）。

---

## 二、字段规范

| 列 | 说明 |
|---|---|
| `period` | 报告期标签：`YYYYQ1`~`YYYYQ4`、`YYYYH1`、`YYYYH2`、`YYYY`（年报）。同一份报告内的"上年同期"用上年同期标签**单独成行**（如 2026H1 报告同时含 `2026H1` 与 `2025H1`） |
| `item` | 报表科目名（与披露口径一致，保留"其中:"前缀科目） |
| `value` | 数值；亏损/流出为负。比率类科目直接写百分数本身（如 `26.99` 表示 26.99%） |
| `unit` | `CNY`（元） / `CNY_per_share`（元/股） / `pct`（百分比） |
| `point_in_time` | **仅资产负债表**：`期末` / `期初`（期初 = 期初资产负债表日，如 2026H1 的期初 = 2025-12-31） |
| `note` | 口径/重分类/来源说明；**派生指标一律标注"派生计算"并给出公式** |

分部表（`_segment_revenue.csv`）基准列：`period,dimension,category,revenue,revenue_pct,gross_margin_pct,yoy_pct,note`。
若标的披露口径不同（如只披露子公司净利率），**允许在基准列后追加列**（例：赛轮追加 `net_profit`、`net_margin_pct`），并须在该标的 README 与 §6.2 登记差异。

## 三、每期更新步骤（财报发布后）

1. **读旧资料**：读 `<research_folder>/data/quarterly/README.md` 与既有 CSV，确认已有 `period` 与口径。
2. **提取**：从当期报告（统一用**合并口径**）提取三张表 + 分部；保留报告内"上年同期"列作为独立 `period` 行。
3. **追加不覆盖**：新增 `period` 的行直接追加；若有会计政策变更 / 追溯调整，另加行并在 `note` 注明"追溯调整"，**不改旧值**。
4. **派生指标**：毛利率、归母净利率、有效税率、资产负债率、有息负债、净负债、资本开支、自由现金流、OCF/净利、EPS 等按需一并写入（`unit=pct` 或 `CNY`，`note` 注明公式）。
5. **更新 README**：刷新"最近更新"日期与数据源；新开标的时补齐数据字典。
6. **登记**：在本规范 **§六 覆盖清单**、`INDEX.md`、`data/logs.json` 与当期会话档案 `TRAE/sessions/` 登记；若该标的出了研究报告，在报告中引用 CSV 作为数据底稿。
7. **同步仓库**：按 `TRAE/WORKFLOW.md` 的推送流程（SSH 或 PAT）提交。

## 四、实时行情（估值用，二级市场）

- 例行校验公开行情接口可访问性：腾讯 `https://qt.gtimg.cn/q=sz<code>`（沪市用 `sh<code>`，GBK 编码）、东财 `https://push2.eastmoney.com/api/qt/stock/get?secid=<mkt>.<code>`（A股 mkt=1 沪 / 0 深）。
- 快照要素：现价、总市值、PE(TTM/动)、PB、股息率、52 周区间、行情日期。
- **行情仅写入研究报告层与 `data/companies.json`（`price` 等字段），不写入季度 CSV**（避免把瞬时价格混入会计时间序列）。

## 五、季度触发节奏（按报告类型）

| 报告类型 | 常见披露窗口 | 需追加的 `period` | 备注 |
|---|---|---|---|
| 一季报 | 4 月末 | `YYYYQ1` + 上年同期 | A 股强制；港股/美股按季 |
| 半年报 | 8 月 | `YYYYH1` + `YYYY-1H1` | 资产负债表须同时给 期末 / 期初 |
| 三季报 | 10 月末 | `YYYYQ3` + 上年同期 | A 股强制 |
| 年报 | 次年 3–4 月 | `YYYY` + `YYYY-1` | 须保留上年同期（年报对比口径） |

- **季报若未披露三表全量**（如 A 股季报仅关键财务数据），可只归档已披露科目，并在该标的 README 与 `note` 注明缺口，**不得虚构未披露科目**。
- 港股/美股标的使用同一 `period` 标签体系；若财年非自然年，须在 README 注明财年口径。

## 七、新标的建档检查清单（Checklist）

1. ☐ 确认 `research_folder` 与仓库内真实目录名完全一致
2. ☐ 建立 `<research_folder>/data/quarterly/`
3. ☐ 按**合并口径**提取：利润表 / 资产负债表 / 现金流量表 / 分部
4. ☐ 保留报告内"上年同期"为**独立 `period` 行**
5. ☐ 资产负债表同时给出 `期末` 与 `期初`
6. ☐ 以 **UTF-8 带 BOM**、long-format 写入
7. ☐ 派生指标标注"派生计算"并给出公式
8. ☐ 编写 `README.md` 数据字典（含披露日期、列结构差异、下一增量）
9. ☐ 执行**会计恒等式自检**：资产=负债+权益、利润表结转（营业利润→利润总额→净利润）、净利润=归母+少数、OCF=流入−流出、FCF=OCF−capex、有息负债/净负债自算
10. ☐ 登记：README"最近更新"、本规范 §6.1、`INDEX.md`、`data/logs.json`、当期研究报告引用
11. ☐ 按 `WORKFLOW.md` 推送流程同步仓库

## 八、扩展指引

- 新标的建档 = 复制本规范 + 按该标的报表结构调整科目清单；**不强行统一科目全集**（不同行业科目不同）。
- 科目清单以该标的年报"财务报表格式"为准。
- 年报归档时把"上年同期"一并保留，并在 README 记录披露日期与审计状态（是否经审计）。
- 历史回溯：可用巨潮资讯（A股）/ 港交所披露易（HK）/ SEC EDGAR（US）补齐过往季度，形成完整时间序列。

## 九、与项目工作流的衔接

- `WORKFLOW.md` 任务分类中，"**季度 CSV 归档**"为财报类任务的**必经环节**（财报更新 / 新立项 / JSON 同步 均触发）。
- 默认执行顺序：**先出研究文件（HTML）→ 再更新季度 CSV（结构化归档）→ 再评估 `data/*.json` → 最后同步仓库**。
- 多设备纪律：同一时段尽量只由**一台设备**写 CSV 与 JSON，避免 `data/` 与 CSV 冲突。
- 与 `PROJECT_INSTRUCTIONS.md` 的三层结构对应：本规范归属"结构化数据层"，是对 `data/*.json` 的**时序补充**（JSON 存工作台消费字段，CSV 存会计时间序列），互不替代。
