本次试运行按你的主提示执行顺序：

1) 先读旧资料（仓库结构 + `data/companies.json` + 工作台代码）  
2) 再产出反馈报告  
3) 最后才提出结构化字段（JSON）修正建议（不直接改动）  

## 发现的问题 1：`research_folder` 与真实目录不一致

工作台会用 `companies.json` 的 `research_folder` 直接拼 GitHub API 路径：

`https://api.github.com/repos/Pjaaden/Stock-Research/contents/<research_folder>`

因此 `research_folder` 必须是“相对仓库根目录的真实路径”（可以包含子目录），否则工作台无法列出该公司报告文件。

本次校验结果见：

- `TRAE/reports/试运行_research_folder校验_20260721.md`

其中至少 3 个公司存在不一致：

- 中国国贸：实际在 `商业地产研究/中国国贸_600007`
- 绿城服务：实际在 `商业地产研究/绿城服务_2869HK`
- 华润万象生活：实际在 `商业地产研究/华润万象生活_01209HK`，但 JSON 里写的是 `华润万象生活_000966`

### 推荐修正策略（优先改 JSON，不动目录）

改目录会影响历史链接和 README 引用，风险更高；更稳妥的方式是把 `data/companies.json` 里的 `research_folder` 改为真实路径，例如：

- `中国国贸_600007` → `商业地产研究/中国国贸_600007`
- `绿城服务_2869HK` → `商业地产研究/绿城服务_2869HK`
- `华润万象生活_000966` → `商业地产研究/华润万象生活_01209HK`

## 发现的问题 2：GitHub 写入在当前环境不可用（缺凭证）

见：

- `TRAE/reports/试运行_GitHub读写测试_20260721.md`

当前环境 `git push --dry-run` 会因为无法交互输入用户名而失败，这意味着：

- 我可以稳定“读仓库、生成报告、给出 JSON 变更建议”
- 但“实际推送到 GitHub”需要你提供 PAT（或在你本机完成推送）

## 下一步我建议你确认两件事

1) 你希望 `research_folder` 的规范是：
   - A：统一使用“相对仓库根目录的完整路径”（包含 `商业地产研究/` 这种前缀）
   - B：只用目录名，不含前缀（那就需要把对应公司目录移到仓库根目录）

2) GitHub 写入希望怎么做：
   - A：你本机 push（我只产出文件与 JSON 变更补丁）
   - B：你提供 PAT，我在当前环境 push

我建议两项都选 A，这样风险最低、可控性最高。
